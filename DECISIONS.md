# Decisions

Each entry: what was decided, why, and its evidence status. "Verified" means checked by a test or measurement
described in `progress.md`; "Decided" means a design choice with no measurement behind it.

| # | Decision | Why | Status |
|---|----------|-----|--------|
| 1 | Static, client-side WebGL2 app; no backend, no build step, no runtime dependencies. ES modules, so it must be served over http (`npm start`), not opened from `file://`. | Master prompt: deployable as a static site, light on an 8 GB machine. | Decided |
| 2 | Shaders are JS string modules (`src/shaders/*.js`). | No fetch, no bundler; works on any static host. | Decided |
| 3 | State in R32F, falling back to R16F; each candidate is probed by building a real framebuffer. State is read with `texelFetch` (NEAREST) and wrapped manually. | Float render targets are an extension in WebGL2; avoids needing float-linear filtering. | Decided. R16F is exercised only by forced tests (`gpu-parity.html` readback) and, before the fix in `progress.md` fact 22, by accident after a context restore; its long-run accuracy is untested. |
| 4 | Convolution is direct (every kernel tap per cell), not FFT. | Simple and correct for R <= 24. The paper's pseudocode also uses direct convolution for small worlds. | Decided. Cost uncalibrated on real hardware. |
| 5 | Kernel: single ring, exponential core (alpha 4), normalised to sum 1. Growth: Gaussian. Update: hard clip, dt = 1/T. Periodic boundary. | Matches the paper and the upstream `bump4` / `gaus` definitions. | Verified by reading both sources; CPU and GPU agree. |
| 6 | Fixed 60 steps/s simulation rate, independent of display refresh; at most 4 steps per frame. | Same behaviour on 60 Hz and 144 Hz screens. | Decided |
| 7 | `FrameFence`: at most 2 frames of GPU work in flight, `gl.flush()` per submitted frame; when GPU-limited, 1 step per frame and the HUD says so. | An open-loop loop built a ~150 s backlog on a slow renderer and froze the page; with the fence the backlog drained in 1.3 s. | Verified on a software renderer only. No defect found in review. |
| 8 | Seed data is copied programmatically, never retyped, from upstream `Python/animals.json` entry `O2u` at a pinned commit (MIT; see `THIRD_PARTY_NOTICES.md`). The RLE's SHA-256 is checked by a unit test. | Legal, reproducible, no invented data. | Verified |
| 9 | Orbium (O2u) uses sigma 0.015, the value stored with that pattern. Other sources say 0.014, 0.016, 0.017. | The stored pattern matches 0.015; 0.014 evaporates, 0.015 and 0.016 persist (for the O2u cells). The 0.014 in the list is the value stored with the *different* pattern O2b, which persists at its own 0.014 (decision 21). | Verified (CPU reference) |
| 10 | Patterns are never rescaled. A pattern runs only with its own radius, T, mu and sigma. | Keeps seed data untouched. Unscaled, Orbium evaporated within 100 steps at R = 8, 10, 11, 12, 15, 16, 20 and persisted at R = 13 and 14. | Verified (CPU, ad hoc). The paper reports approximate scale invariance when a pattern is resampled (R > 12); resampling is not implemented. |
| 11 | Startup: Orbium with its own parameters by default. If the URL changes any required parameter (today only `?radius=`), show the old random-noise start with the requested radius and an on-screen note. | Keeps `?radius=` usable for experiments instead of forcing 13 or silently showing a dying pattern. | Decided; behaviour verified. Forcing radius 13 instead would be a small change. |
| 12 | GPU/CPU parity: strict pointwise for a per-pattern horizon, at the existing tolerance of 1e-3 for float32 state (1e-2 for the float16 fallback; neither changed), over 200 steps for O2u and 20 for O2b (see decision 23); beyond that compare observables (mass, centroid) only. | The system is sensitive to initial conditions, so pointwise error is not meaningful at long horizons. | Verified (see `progress.md`) |
| 13 | Placement copies pattern row 0 to the lowest grid row, so Orbium appears vertically mirrored relative to upstream pictures. | Exact copy with no flipping. The paper reports reflection invariance (Fig. 6d), and the placed state is what is tested. | Decided |
| 14 | Browser results from a software renderer are never described as hardware-GPU results, and the exact renderer string is recorded with a result. The earlier results in `progress.md` (verified facts 1 to 13) came from headless Chromium on a software renderer (ANGLE with SwiftShader). The results recorded on 31 Oct 2026 (facts 14 onward) came from the Claude desktop app's built-in browser, whose WebGL context reports `ANGLE (AMD, AMD Radeon(TM) Graphics (0x00001681) Direct3D11 vs_5_0 ps_5_0, D3D11)`. That string names an AMD GPU behind ANGLE/Direct3D 11; it is the evidence, and nothing beyond it (driver, browser version, power state, or any frame-rate figure) is claimed. | Honesty about what was verified. | Policy |
| 15 | Default grid is 128 (was 256). | Orbium is 20 cells: twice as large on screen, 4x cheaper per step on weak hardware. Grid-size independence (64 vs 128) is verified, so the organism is unchanged. Two unit-test assertions that hard-coded 256 now read `DEFAULT_PARAMS.gridSize`. One-line revert in `src/config.js`. | Decided; behaviour verified in the app |
| 16 | The App owns all user-facing state (paused, speed, live parameters, palette); the UI only calls its methods and renders from `onStatus()` snapshots. Pause/step/reset change flags and queued work consumed by the one existing loop; per-frame step planning is the pure `planFrameSteps`. | No second loop or competing update path; single-step semantics are unit-testable without a GPU. | Verified (unit tests; ui-flow page checks at most one pending animation frame after 25 rounds of rapid play/pause toggles and resets) |
| 17 | Reset restores the initial state and the initial parameters; it keeps play/pause and speed. Leaving the tour (finish or skip) resets and plays. | Matches the planned semantics in `progress.md`; the explorer always starts from the verified organism, never from an experiment's leftovers. | Decided |
| 18 | Guided experiment lowers sigma 0.015 to 0.011 after a 60-step observation. Not 0.014. | A *settled* Orbium survives 0.014 and 0.013 and fades at 0.012 and below; 0.014 only kills the freshly placed seed. A first draft using 0.014 would have shown a surviving organism under a "it faded" explanation. | Verified (CPU: `tests/unit/experiment-evidence.test.js`; GPU in the real app via ui-flow, mass 0) |
| 19 | Only mu, sigma and T are live-adjustable (uniforms). Radius and grid are fixed. Slider ranges are a subset of `LIMITS` (`UI_RANGES`). | They need no GPU reallocation and cannot raise the per-step workload; radius changes the organism (decision 10). | Verified (unit tests) |
| 20 | Two display palettes selected by a shader uniform. The renderer defaults to viridis so existing colour-map browser checks are unchanged; the app selects "observatory", labelled **Ocean** in the interface (renamed from "Observatory" on 3 Nov 2026 so it is not confused with the Observatory card; the internal id is unchanged). | Better contrast against the interface; viridis kept as an option. Display only: simulation state is never modified. | Verified (gpu-parity page unchanged and passing) |
| 21 | Pattern library: exactly two entries, O2u (default at launch) and O2b, in a static frozen registry (`PATTERN_LIBRARY`, `getPattern` in `src/simulation/patterns.js`; ids are looked up there only, nothing is loaded at runtime). Both run at R = 13, so selecting one reuses the existing GPU resources (kernel texture, state textures, program): one state upload plus a reset, nothing recreated. `App.selectPattern(id)` swaps the base parameters, initial state and label, then resets through the same path as Reset; so Reset and the `R` key restore the *selected* pattern, play/pause and speed are kept, and selecting the pattern already shown restarts it. It is refused when the world's radius is not 13 (the `?radius=` noise start): the selector is then shown locked with a reason. O2b is copied programmatically from the same pinned upstream commit as O2u (own SHA-256, own reference decode made by running upstream's decoder source; see `THIRD_PARTY_NOTICES.md`) and uses its own stored sigma 0.014. | The kernel is built once from the radius and patterns are never rescaled (decision 10), so a pattern can only be shown at its own radius. | Verified (unit tests; `ui-flow.html` on the reported AMD renderer, including 25 O2u/O2b round trips with the same simulation, kernel texture, state textures and program in place). Context loss and restore is a separate operation and does not reuse resources: it rebuilds every GPU resource (`initGpu`) and re-uploads the *selected* pattern's state, which `ui-flow.html` also checked after selecting O2b. Such a restore used to come back with float16 state where the app had started in float32; that was fixed separately (`progress.md` fact 22) |
| 22 | The guided tour runs on O2u only: it selects O2u when it opens and again when it is left, so it always starts and ends with O2u selected, even when opened from O2b. The selector is locked while the tour is open. The tour's text and experiment (sigma 0.015 to 0.011, decision 18) were measured for O2u and are not claimed for O2b. | Mid-tour switching would break the experiment's gates, and the evidence is for O2u. | Verified (`ui-flow.html`: tour started from O2b, whole tour run, ends on O2u) |
| 23 | GPU/CPU parity is judged on two different things. *Pointwise* equality is asserted over a short horizon, at the existing tolerances: 1e-3 when the state format is float32 (every run recorded here) and 1e-2 for the float16 fallback (`parityToleranceHalf` in `orbium-gpu.js`). Neither tolerance was changed. The horizon is: 1, 5 and 20 steps for every pattern, extended to the 100 and 200 step checkpoints for O2u only. *Long-term correctness* is judged by behavioural metrics only: values stay in [0,1], mass persistence (0.8 to 1.1 of the seed), shape correlation (at least 0.85), steady motion, GPU against CPU observables (mass within 1, centroid within 2 cells), grid-size independence, and no WebGL errors. **Long-term pointwise numerical equivalence between GPU and CPU is not claimed**, for any pattern. For O2b the 200-step pointwise check was removed (owner-approved) rather than loosened: measured on the reported AMD renderer, its error was 1.77e-4 at step 100 and 1.70e-3 at step 200 against the 1e-3 tolerance, while its observables agreed (worst mass difference 0.0033, worst centroid difference 0.0026 cells). Neither tolerance is changed; only the horizon is. | O2b is more sensitive than O2u (an ad hoc CPU comparison of the reference against a float32-accumulating variant gave 2.8e-4 at step 150 for O2b, 5.7e-5 to 9.0e-5 for O2u). The GPU error is larger than that float32 variant's (8.4e-5 at step 200), and the cause was not isolated (shader `exp()`, fused multiply-add, tap order, or the driver are all untested). | Decided; the numbers are Verified (`orbium-gpu.html`), the CPU comparison is ad hoc (script not in the repo) |
| 24 | Observatory readback: the state is copied to the CPU asynchronously. `AsyncReadback` (`src/gl/readback.js`) queues `readPixels` into a PIXEL_PACK_BUFFER and a fence; every animation frame then only asks whether the fence has signalled (as FrameFence does), and once it has, copies the finished data out with `getBufferSubData`. No call waits for the GPU to finish work. The final copy is synchronous CPU work on the main thread. Each request is tagged with the simulation generation and an epoch *at submission*, so a result describes the state it was taken from, however late it arrives. At most one request is in flight. Only READ_FRAMEBUFFER and PIXEL_PACK_BUFFER are bound, and both are restored to their previous bindings in `finally`, also when a call throws. Read format: RED/FLOAT when the framebuffer reports it (4 bytes per cell: 16 KiB at grid 64 to 1 MiB at 512), otherwise RGBA/FLOAT (16 bytes per cell); a float16 state reports RED/HALF_FLOAT and is read as RGBA/FLOAT. A failure (exception, or no signal within 600 polls) shows "unavailable"; the simulation keeps running. On context loss the readback is dropped without GL calls and recreated with the GPU resources. | The owner's requirement: no wait for the GPU in the frame path. Synchronous `readPixels` would wait for all queued GPU work; a GPU reduction would need new shaders. | Strategy as proposed in the Observatory plan. Behaviour Verified (gpu-parity: exact copies, tag at submission while the state moved 5 steps on, float32 and float16, bindings restored including on a thrown call, no GL error; ui-flow: lifecycle). Main-thread cost measured in the built-in browser on the AMD renderer with in-page probes (not in the repo), warm: `getBufferSubData` median 1.0 / 1.1 / 3.2 / 3.6 ms at grids 64 / 128 / 256 / 512 (2.2 to 8.5 ms at 512 with the GPU loaded); fence signalled after 1 to 2 frames, at most 6 seen. The first copy at grid 512 after page load took about 45 ms (cold); a new readback is created after every context restore. Frame-rate effect in an ordinary browser is unmeasured |
| 25 | Observatory metrics, named for what they compute (`src/simulation/observables.js`): **mass** = sum of all cell values; **active area** = number of cells whose stored value is strictly greater than the active threshold; **centroid** = per-axis circular mean of the values on the torus, from row and column sums, with its concentration R (0..1) per axis, shown only when mass is at least the minimum mass and R is at least the minimum concentration on both axes ("none (no mass)" / "not meaningful (spread out)" otherwise). A spread in cells, (n/2pi)sqrt(-2 ln R), is computed but not displayed. **Values (approved by the owner on 3 Nov 2026):** active threshold 0.01, minimum mass 1e-3, minimum concentration 0.5. | Reproducible in the repo (`tests/unit/observables.test.js` with the fixtures): the 0.01 boundary is strict on the stored float32 value; seed active areas 220 (O2u) and 205 (O2b) against 222 and 207 non-zero cells; empty and trace fields give "no mass"; uniform, nearly uniform and evenly split fields fall below R 0.5 while both seeds are above it; the spread is grid-independent (O2u at 64 and 128 within 0.05 cells); equal to the earlier per-cell centroid. From an ad hoc CPU script, not in the repo: in evolved O2u and O2b states only 2 to 5 cells lie in (0, 0.01], carrying at most 3.4e-4 of the mass; float16 rounding changed the active count by 0 and the mass by at most 8e-4; R is 0.93 (grid 64) to 0.98 (128) for the organisms, 0.82 for the noise disc, 0.00 for two copies half a grid apart; a fading organism keeps R >= 0.94 until its mass reaches exactly 0. | Definitions Decided; values approved by the owner (3 Nov 2026) on the evidence listed |
| 26 | Observatory sampling: polled every frame, submitted after the frame's steps and draw (before the frame fence), never while the loop is GPU-limited, only when the generation has changed (paused: only a Step produces a sample), and one at a time; so the rate is a ceiling, not a guarantee, and under sustained GPU pressure no samples are taken (the card then says so). Reset, a pattern switch and a context loss increase the epoch, clear the history and discard any result in flight. The App emits a status update when a sample lands. Chart: canvas 2D, vertical axis from 0, text equivalent in a visible summary and the canvas `aria-label`. The tour and selector are unaffected. **Values (approved by the owner on 3 Nov 2026):** minimum interval 250 ms (500 ms at grid 512), history 240 samples, readback failure after 600 unsignalled polls, and the sampled-metric tolerances against the CPU reference at generations 20 and 100: |dMass| <= 0.01, |dCentroid| <= 0.01 cells, |dActive| <= 2. | Reproducible in the repo: the bytes-per-second bound (at most 8 MiB/s in the worst case, RGBA at grid 512; `tests/unit/sampler.test.js`) and the measured sampled-metric differences, which `orbium-gpu.html` check E prints (worst on the reported AMD renderer: |dMass| 2.91e-4 for O2b at generation 100, |dCentroid| 7.0e-5 cells, |dActive| 0). In-page probes, not in the repo: `computeObservables` median 0.1 / 0.2 / 0.4 / 1.3 ms at grids 64 / 128 / 256 / 512 (1.1 to 1.7 ms at 512 with the GPU loaded); at grid 512 on this machine the loop was GPU-limited in every check over 20 s, so no samples were taken. History size and the poll limit are sizing choices without measurements. | Rules Decided and Verified (`tests/unit/sampler.test.js`, `orbium-gpu.html` check E, `ui-flow.html`); values approved by the owner (3 Nov 2026) on the evidence listed |
| 27 | Production headers come from one `_headers` file at the repository root (read by Cloudflare Pages, Workers static assets and Netlify): the meta CSP plus `frame-ancestors 'self'` (`'self'` because `ui-flow.html` frames `index.html`), `nosniff`, `Referrer-Policy: no-referrer`, a deny-list `Permissions-Policy`, and `Cache-Control: no-cache` so unhashed modules are revalidated on every load.
